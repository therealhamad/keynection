# Keyshots — Technical Overview

This document describes the architecture and implementation of **Keyshots**, a Chrome extension that provides a keyboard-driven, Raycast-style command overlay for executing actions across Gmail, Slack, Notion, GitHub, and Google Calendar, with optional AI-powered (Gemini) features.

---

## 1. High-Level Architecture

Keyshots is a **Chrome Extension (Manifest V3)** with three main execution contexts:

| Context | Role | Key Files |
|--------|------|-----------|
| **Background (Service Worker)** | Command dispatch, OAuth, all outbound HTTP (Gmail, Slack, Notion, GitHub, Calendar). Runs in extension origin; not subject to page CORS. | `background/service-worker.js` |
| **Content Script** | Injected into every page. Injects overlay DOM, listens for toggle, delegates UI to overlay/component scripts. Runs in page context but with extension APIs. | `content/content-script.js` |
| **Page Context (via injected scripts)** | Overlay UI, command palette, forms, context detection, Gemini calls. Same origin as the host page for `fetch`; therefore external API calls are routed through the service worker to avoid CORS. | `overlay/*`, `components/*`, `utils/*` (except storage/api which message the background) |

**Data flow (simplified):**

- User presses **Option+Space** (Mac) or **Ctrl+Shift+K** (Win/Linux) → `chrome.commands` fires in service worker → worker sends `toggleOverlay` to active tab → content script shows/hides overlay.
- Overlay shows **command palette** (search + list of actions). Actions can be base (Send Email, Send Slack, Create Notion Page, Settings) or **context-aware** (e.g. “Email this quote”, “Summarize for Slack”, “Extract tasks”, “Generate standup”).
- **Context** (selection, page type, article detection) is computed in the content script context via `KeyshotsContext.detect()`.
- Any action that needs to call an external API (Gmail, Slack, Notion, GitHub, Calendar) is implemented by the **content script sending a message** to the service worker; the **service worker performs the `fetch`** and returns the result. This avoids CORS, since the worker runs in the extension origin.
- **Gemini** is called with `fetch` from the content script (generativelanguage.googleapis.com is in `host_permissions`), or could be moved behind the worker for consistency.
- **Persistence** is via `chrome.storage.local` (tokens, webhook URL, API keys, preferences), abstracted by `KeyshotsStorage`.

## 2. Manifest and Permissions

- **manifest_version: 3**
- **permissions:** `storage`, `activeTab`, `identity`
- **host_permissions:**  
  `hooks.slack.com/*`, `api.notion.com/*`, `www.googleapis.com/*`, `generativelanguage.googleapis.com/*`, `api.github.com/*`
- **oauth2:** Single Google OAuth client with scopes:
  - `https://www.googleapis.com/auth/gmail.send`
  - `https://www.googleapis.com/auth/calendar.readonly`
- **background:** Single service worker script.
- **content_scripts:** One entry matching `<all_urls>`, `run_at: document_end`, injecting a long list of JS files (storage, api-client, gmail-api, gemini-client, context-detector, activity-fetcher, ui-helpers, command-palette, all forms, overlay, content-script) and one CSS file (overlay styles). Order defines dependency/initialization order.
- **commands:** `toggle-overlay` with the above keybindings.

All extension scripts are listed in the manifest; there are no dynamic `chrome.scripting` injections for the main flow (the overlay is DOM injection, not script injection).

## 3. Execution Contexts in Detail

### 3.1 Service Worker (Background)

- **Lifetime:** Event-driven; may suspend when idle (MV3).
- **Responsibilities:**
  - **Command listener:** `chrome.commands.onCommand` → `chrome.tabs.sendMessage(activeTab, { action: 'toggleOverlay' })`.
  - **Message router:** `chrome.runtime.onMessage` handles actions: `gmailSendEmail`, `gmailCheckConfigured`, `gmailSignOut`, `slackSendMessage`, `notionFetchDatabases`, `notionCreatePage`, `githubFetchActivity`, `notionFetchActivity`, `calendarConnect`, `calendarFetchActivity`. Each handler performs the corresponding HTTP request and calls `sendResponse` with a result object.
- **Gmail:** Uses `chrome.identity.launchWebAuthFlow` for OAuth (not the deprecated `getAuthToken`). Builds Google OAuth URL with `response_type=token`, stores access token in `chrome.storage.local`, verifies with `tokeninfo` when reusing. Sends email via `https://gmail.googleapis.com/gmail/v1/users/me/messages/send` (POST, raw RFC 2822 message).
- **Calendar:** Separate OAuth flow with `calendar.readonly` scope; token stored under a different key. `calendarFetchActivity` calls Calendar API `calendars/primary/events` with `timeMin`/`timeMax` (last 24 hours), filters out cancelled and declined, maps to a simple `{ summary, start, duration, attendees, url }` list.
- **Slack:** POST to user-configured webhook URL (from storage); no OAuth.
- **Notion:** Bearer token from storage; POST/GET to Notion API (search, create page).
- **GitHub:** Uses PAT from storage. Two-step: (1) `GET /users/{username}/events` to find repos with recent `PushEvent`s in the last 24h, (2) for each such repo, `GET /repos/{owner}/{repo}/commits?author={username}&since={iso24h}&per_page=50` to get actual commit messages. Merges and deduplicates by message, returns `{ success, commits: [...] }`.

All outbound requests are therefore made from the service worker, avoiding CORS issues that would occur if the content script (running on e.g. `mail.google.com`) called those APIs directly.

### 3.2 Content Script

- Injected once per page load; maintains a flag `overlayInjected` so the overlay DOM is only created once.
- **Message listener:** On `toggleOverlay`, calls `toggleOverlay()`.
- **Local keybinding:** Also listens for Option+Space / Ctrl+Shift+K on the document and calls `toggleOverlay()` (backup if the command does not fire).
- **Overlay DOM:** Creates a single root `#keyshots-overlay` with backdrop, modal, header (search input), content area, footer. Appends to `document.body`. Search is the main command palette filter; content area is swapped by view (command list, forms, messages).
- **Visibility:** Toggle adds/removes class `keyshots-hidden` (CSS controls visibility). On show, resets to command palette and focuses search.
- Exposes `window.KeyshotsApp = { show, hide, toggle }` for other scripts in the same context.

### 3.3 Overlay and Components (Same Context as Content Script)

- **KeyshotsOverlay:** State machine for view (`currentView`), selected index in command list, keyboard handling (Escape → back/close, Arrow Up/Down + Enter in palette, Cmd/Ctrl+Enter to submit forms). `showCommandPalette()` re-renders the palette and shows header/footer; `showView(viewName, options)` hides header/footer and delegates to the right component (gmail, slack, notion, settings, smart-email, smart-slack, smart-tasks, standup).
- **KeyshotsCommandPalette:** Builds a list of commands: base commands (Send Email, Send Message, Create Page, Settings) plus context-dependent “smart” commands from `KeyshotsContext.detect()` (e.g. “Email this quote” when there is selection, “Summarize for Slack” on articles, “Extract tasks” when selection looks like tasks, “Generate standup”). Renders grouped by category (e.g. Smart Actions vs Actions), with icons and optional badge. Search filters by name/description/keywords. Click or Enter runs the command’s `action()` (e.g. `KeyshotsOverlay.showView('gmail')` or `showView('standup')`).
- **Forms (Gmail, Slack, Notion, Settings):** Each has a `render()` that replaces `#keyshots-content` with the form HTML and binds submit/cancel. Gmail uses the Gmail API (via messaging to the worker); Slack uses `KeyshotsAPI.sendSlackMessage`; Notion uses `KeyshotsAPI.createNotionPage` / `fetchNotionDatabases`. Settings read/write via `KeyshotsStorage` and optionally test connections (e.g. GitHub test uses the same `githubFetchActivity` message).
- **Smart forms (Smart Email, Smart Slack, Extract Tasks):** Rely on `KeyshotsContext` and `KeyshotsGemini`. They request AI-generated content (e.g. email subject/body, Slack summary, task list) then hand off to the same Gmail/Slack/Notion APIs or clipboard.
- **Standup flow:** Multi-step: (1) Fetch activity via `KeyshotsActivityFetcher.fetchAllActivity()` (GitHub commits, Notion tasks, Calendar meetings — each via a message to the service worker). (2) Show loading steps then an activity review screen with checkboxes per source. (3) User can add “blockers” and click “Generate Update”. (4) Gemini is called with a prompt that includes selected commits/tasks/meetings/blockers to produce a standup message. (5) User edits the message and posts to Slack via `KeyshotsAPI.sendSlackMessage`.

## 4. Messaging and CORS Bypass

- **Content script → Service worker:** `chrome.runtime.sendMessage({ action: '...', ...params }, callback)`. The worker’s `onMessage` returns `true` where it calls `sendResponse` asynchronously (e.g. after `fetch`).
- **Slack / Notion / GitHub / Calendar:** Content script never calls these APIs directly. It sends a message; the worker performs `fetch` and returns `{ success, data or error }`. This is the standard MV3 pattern to avoid CORS when the content script runs on arbitrary origins (e.g. Gmail, Notion).
- **Gmail send:** Same pattern: content script asks the worker to send an email; worker uses the stored OAuth token and calls Gmail API.

---

## 5. Storage and State

- **chrome.storage.local** is used for:
  - Gmail access token (worker-managed).
  - Calendar access token and `calendar_connected` flag.
  - User-configured: Slack webhook URL, Notion token, Notion database list, Gemini API key, GitHub PAT and username.
- **KeyshotsStorage** wraps `chrome.storage.local.get/set/remove` with a small key namespace (e.g. `KeyshotsStorage.KEYS.SLACK_WEBHOOK`).
- **In-memory state:** Overlay view and selected index live in `KeyshotsOverlay`. Standup flow keeps `standupData` (commits, tasks, meetings, selected indices, blockers) in the component object. No separate global store.

---

## 6. OAuth Flows

- **Gmail:** `launchWebAuthFlow` with Google OAuth URL (client_id, redirect_uri = `https://<extension_id>.chromiumapp.org/`, scope gmail.send, response_type=token). User signs in in a popup; redirect URL hash contains `access_token`; worker parses and stores it. No refresh token in this flow; when token is invalid, user must re-auth.
- **Calendar:** Same mechanism with scope `calendar.readonly` and a separate storage key. “Connect” in settings sends `calendarConnect` to the worker; worker runs the flow and stores the token and sets `calendar_connected`.

---

## 7. Context Detection and Smart Actions

- **KeyshotsContext.detect():** Returns `{ hasSelection, selectedText, pageTitle, pageUrl, pageType, isArticle, pageContent, wordCount }`. Uses `window.getSelection()`, `document.title`, `location.href`, and heuristics for `pageType` (e.g. github, gmail, notion) and `isArticle` (word count + `<article>`, `og:type`, or body class names). `extractMainContent()` prefers selection, then `<article>`, then `<main>`, then body text (capped).
- **Smart commands:** Built from context (e.g. if `hasSelection` → “Email this quote”, “Share to Slack”; if selection looks like tasks → “Extract tasks”; if `isArticle` → “Email this page”, “Summarize for Slack”). “Generate standup” is always offered as a smart action.

---

## 8. Gemini Integration

- **KeyshotsGemini** uses a single endpoint (e.g. `gemini-3-flash-preview:generateContent`). API key is read from storage.
- **generateContent(prompt):** Single request/response; returns `data.candidates[0].content.parts[0].text`.
- **Higher-level methods:** `generateEmailFromContext`, `generateSlackSummary`, `extractTasks` build prompts from context/text and parse JSON from the model output (with fallback for markdown-wrapped JSON). Used by smart email, smart Slack, and extract-tasks forms.
- **Standup:** Custom prompt in the standup flow that includes commits/tasks/meetings/blockers and asks for a structured Slack-style standup message.

---

## 9. Standup Feature (End-to-End)

1. User chooses “Generate Standup Update” in the palette.
2. **Activity fetch:** `KeyshotsActivityFetcher.fetchAllActivity()` runs in content script and:
   - If GitHub token + username: sends `githubFetchActivity` → worker fetches user events, then repo commits for repos with recent pushes.
   - If Notion token: sends `notionFetchActivity` → worker runs Notion search, filters by last 24h, maps to tasks with title/status/lastEdited.
   - If calendar connected: sends `calendarFetchActivity` → worker fetches primary calendar events in last 24h, filters and maps to meetings.
3. Results are aggregated into `{ commits, tasks, meetings, errors }`. Standup component stores them and shows a review UI with checkboxes and optional “blockers” text.
4. User clicks “Generate Update” → prompt is built from selected items + blockers → `KeyshotsGemini.generateContent(prompt)` returns a standup message.
5. User edits the message and submits → `KeyshotsAPI.sendSlackMessage(message)` posts to Slack (webhook from storage).

---

## 10. UI and Styling

- **Overlay:** Fixed full-screen container; modal is centered. CSS uses high specificity and resets (e.g. `all: revert`, `!important`) to avoid host page styles affecting the overlay. Dark theme, purple/accent highlights.
- **Command palette:** Search at top; sections (e.g. “Smart Actions”, “Actions”); list items with icon, name, description, optional badge. Active item highlighted; keyboard navigation updates selection.
- **Forms:** Consistent layout with back button, title, form groups, primary/secondary buttons. Loading and error/success states are shown in the same content area or via small messages.

---

## 11. Security and Token Handling

- **Tokens and secrets** (Gmail, Calendar, Notion, GitHub PAT, Gemini API key, Slack webhook) are stored in `chrome.storage.local`. They are not sent to any third party other than the intended APIs (Google, Slack, Notion, GitHub) when the user triggers the corresponding action.
- **OAuth:** No refresh tokens in the current Gmail/Calendar flows; access tokens can expire and require re-auth. Redirect URI is the extension’s chromiumapp.org URL.
- **Content script** runs in the page context and can read page content and selection for context; it does not expose tokens to the page. API calls are done in the service worker.
